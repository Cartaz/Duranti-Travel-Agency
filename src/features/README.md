# Features

Feature modules contain user workflows and orchestration. They depend on domain contracts and repository interfaces, not browser storage primitives.

Implemented / active:

- `storage-lab/` — regression UI for IndexedDB, OPFS and the legacy diagnostic Vault; intentionally kept out of the primary everyday navigation.
- `trips/` — travel-book index backed by local persistence, trip creation/editing, status grouping, chapter detail navigation, archive/restore lifecycle and an optional exact minor-unit budget in the trip currency. Everyday screens use progressive disclosure: trip creation starts with title and dates, while subtitle, status, currency, budget and notes stay under optional details. Return dates are constrained by departure and are automatically realigned if departure is moved beyond an existing return; edits that would exclude saved trip days report the exact conflicting day and the proposed range in readable Italian dates.
- `days/` — ordered trip-day pages with local create/edit workflows, trip ownership validation and travel-date range enforcement. The date picker is bounded to the trip interval and shows that interval with readable Italian dates instead of raw ISO values. Each day can now store an optional long-form journal entry separately from its short summary; existing day records remain compatible because the field is optional. The trip-day list marks pages that already contain a journal entry. New days can start blank or from a reusable day template; template-backed creation opens the generated day directly so its blocks can be completed immediately.
- `planner/` — persistent day editor with text, heading, checklist, divider, place, transport, accommodation, restaurant, activity and expense blocks, atomic up/down reordering, soft-delete and read-only archived trips. The everyday add flow now uses one compact “Aggiungi alla giornata” control: Spostamento, Attività, Mangiare and Dormire are presented as intent-first choices, while place, expense and editorial blocks live under secondary options. The legacy ten-button toolbar is hidden in this guided route, and a newly created block is brought into view automatically. When a day contains journal text, it is rendered as a readable diary section before the itinerary.
- `media/` — day-level local photo/video gallery backed by the existing `Media` metadata table and OPFS binary storage. Users can import multiple local images/videos, preview them in the day page, add a short caption, reorder them, associate them with a place or itinerary stop, open originals in a keyboard-accessible full-screen viewer and remove them with the shared in-app confirmation. Reservation attachments are excluded from the gallery even when they belong to the same day. Reservation-derived stop links use the reservation identity so they remain stable across itinerary reconciliation. Photo imports are capped at 25 MiB and videos at 250 MiB per file; archived trips remain read-only. Caption, association and ordering fields are optional metadata, so the existing IndexedDB schema/version remains compatible.
- `places/` — manually saved local places linked from planner blocks with universal Google Maps URLs; no Google API key or automatic geocoding required. Place editing now keeps only name and address visible by default; city, country, category, coordinates and notes live under expandable optional details, with explicit guidance that latitude/longitude must be supplied together. Place removal now uses the same in-app confirmation pattern as the other destructive planner actions.
- `reservations/` — transport, accommodation, restaurant and activity records linked atomically to planner blocks, with local wall-clock date/time, separate IANA timezone, optional saved place and booking link; reservation saves also synchronize an itinerary entry used by the day timeline, with read-only fallback for legacy reservations not yet persisted into itinerary data. The start date is fixed to the owning travel day and users choose only the start time; optional end date/time fields prevent impossible ranges and use transport-specific labels such as partenza/arrivo. Service errors include the conflicting date/time and the allowed trip boundary. Reservation editing keeps title, timing, status and place visible while provider/code/timezone/link/notes and the attachment live in expandable optional sections. Reservation/block deletion and attachment removal now use readable in-app confirmations instead of browser confirm popups. Each saved reservation can own one local PDF/image attachment stored in OPFS with metadata in IndexedDB, including replace/remove cleanup.
- `itinerary/` — editable day timeline ordered first by local start time plus a read-only cross-day overview on the trip page. Normal manual/reservation source badges are hidden from everyday screens; users only see a plain-language warning when a tappa actually needs attention or can be refreshed from its reservation. Manual-tappa deletion and broken-link cleanup use an in-app confirmation instead of browser confirm popups. A manual tappa inherits its start date from the owning day, so users choose only its start time; optional end date/time remain bounded by the trip range.
- `expenses/` — exact minor-unit expense records linked atomically to planner blocks, payer assignment restricted to trip participants, per-day/category/payer summaries, trip budgets, and optional explicit per-expense FX into the trip currency using only a user-supplied rate and exact integer conversion math. Expense entry now starts with amount, currency and description; category, payer, time, notes and FX stay under optional details. The expense date is derived from its owning day so users can optionally choose only the time, eliminating cross-day date errors from normal entry. Expense deletion uses the same in-app confirmation pattern and shows the saved amount when available.
- `templates/` — reusable local day templates stored in the existing `templates` table. Built-in presets cover travel day, city visit, museum/activity and excursion; “Pagina vuota” preserves the old creation flow. Editable days can also be saved as personal templates from the day page. Personal templates preserve only reusable text/headings/checklists and empty structural placeholders; trip-specific reservation/place/expense IDs and values are stripped, checklist state is reset, and the same whitelist is re-applied when a template is instantiated. Built-in and personal templates are labeled separately in the new-day picker. Personal templates can be renamed inline or removed with an in-app confirmation; built-in presets are protected at service level. Deletion tombstones the personal template so historical `Day.templateId` references remain untouched. Applying a template records `Day.templateId` and rolls back the newly-created day/blocks if template application fails.
- `travelers/` — reusable system-level traveler profiles and trip memberships with role management and duplicate-membership protection; identity documents remain behind the encrypted document boundary.
- `ui/` — global readable form validation replaces truncated browser validation bubbles with an in-app multiline notice, focuses the first invalid field, keeps legacy alert/toast text wrappable, and reports concrete min/max date or time values when a browser constraint is violated. Itinerary titles and confirmations wrap instead of using ellipsis truncation. A shared inline confirmation component is now used across itinerary, reservations, expenses, places and basic planner blocks.

Planned next:

- `templates/` — optional versioning/update flow when a saved personal structure evolves.
- `media/` — optional cover selection, capture-time metadata and lightweight organization tools without uploading originals to a remote service.
- `planner/` — smarter context defaults without reintroducing toolbar density.
- `places/` — reusable place library, richer map UI and provider-assisted lookup only when explicitly enabled.
- `reservations/` — multiple attachments and richer booking-specific fields without increasing the default form density.
- `itinerary/` — optional filtering/printing for the cross-day overview and, if needed, explicit user-selected relinking to a concrete reservation/block pair without fuzzy matching.
- `expenses/` — richer budget views, reconciliation and optional saved FX-rate metadata/source notes.
- `travelers/` — encrypted identity-document UI, addresses/preferences and membership reconciliation tooling.
- `vault/` — production encrypted export/import UI.
- `book/` — book/chapter/page presentation state and page-turn interaction.
